# The PDF asks for ten or more cases — the brief's "three" is a Friday slice, not the target

Read from the official PDF, §"How to evaluate your solution", 2026-08-28.

Exact wording: *"Ten or more cases is a good target when the task allows it. Include one
challenging case and explain what it revealed."*

**Settled 2026-08-28 (evening):** we are submitting **three** cases. Ten was never a
requirement, and with the experiment finished the remaining hours buy far more under
Reproducibility and End-to-End Quality than a fourth case would buy here. Six credible cases beat
ten rushed ones, and three audited ones beat six hurried ones.

**How to apply:**
- The README **must** state in one sentence why the benchmark is three cases. Silence reads as an
  oversight; the stated reason (depth of external sourcing per case, and honest auditing) reads
  as judgement.
- Case 002 is the deliberately hard one and the README must say what it revealed — that is an
  explicit rubric ask.
- Do not add cases unless packaging is finished. See [[constraint-packaging-is-the-gap]].
